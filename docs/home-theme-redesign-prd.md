# 产品需求文档：首页风格按钮与配色主题扩展

**版本**：1.0
**日期**：2026-10-19
**作者**：Sarah（产品负责人）
**质量评分**：93/100

---

## 摘要

当前头部「风格」下拉只有 3 套皮肤，且主题色只通过 `--neo-*` 变量影响头部背景、Logo、搜索框等少数元素。首页大量组件（轮播、角色面板、信息流、横条）与列表页（工具栏、卡片、角色侧栏）仍写死 `#fff8ef` / `#ffd84f` / `#ff7a7a` / `#bcaeff`，切换风格时页面变化很小，用户感知不到"换肤"。

本需求将主题系统扩展为 **5 套完整配色**，每套定义整页背景、面板、导航、强调色与文字色，并把首页首屏、头部、首页其余板块、列表页与卡片的写死颜色替换为主题变量。风格按钮保留下拉，每项增加"背景 / 主色 / 强调色"三色块预览。

---

## 问题陈述

**现状**：
- 3 套皮肤颜色覆盖不全，大量元素不随主题变化。
- 页面大底色固定为深色，浅色主题也出现大块深色背景，风格不彻底。
- 下拉里只有色块与文字，用户难以在切换前判断整体效果。

**目标**：让每套风格在**整页范围**内可感知——背景、导航、卡片、按钮、标签、悬浮态都跟着变，同时保持 Neo-brutalism 的黑描边与硬阴影体系。

**业务影响**：换肤是首页的个性表达入口，覆盖越完整，用户越愿意停留和尝试；也能让不同分站/角色页面有更强的视觉区分。

---

## 成功指标

- **覆盖度**：每套主题下，页面背景、头部导航、首页 Hero、轮播卡框、移动端信息流、列表工具栏、ModCard、角色侧栏、标签/按钮均使用主题变量。
- **可感知度**：切换主题后，首屏至少有 6 类元素视觉变化（背景、导航、面板、强调色、标签、按钮）。
- **一致性**：所有前台正文对比度满足 WCAG AA；不出现黑底黑字/白底白字。
- **技术指标**：首页与 `/mods` 仍然保持静态预渲染；切换无闪烁（cookie + 首帧内联脚本）；切换不引起布局偏移。
- **可用性**：下拉每一项都能在 1 秒内分辨出主题差异（三色块预览）。

## 用户画像

### 主画像：喜欢折腾外观的访客
- 会尝试不同风格，希望站点"像自己的"
- 对高饱和、刺眼的配色敏感，希望有低饱和选择
- 在手机与桌面都会访问

### 次画像：普通浏览者
- 不主动切换，但首屏观感决定是否继续浏览
- 希望文字清楚、按钮醒目、不过度花哨

## 用户故事与验收标准

### 故事 1：一键换肤，整页跟着变

**作为**访客
**我希望**切换风格后整页颜色都变化
**以便**获得明显的视觉切换

**验收标准：**
- [ ] 页面大底色随主题变化（不再固定深色）。
- [ ] 头部导航、Logo、搜索框、横条使用主题色。
- [ ] 首页 Hero、轮播卡框、移动端信息流、横条使用主题色。
- [ ] 列表页工具栏、ModCard、角色侧栏、标签/按钮使用主题色。
- [ ] 保留黑色 4px 描边与硬阴影，不因主题变化而消失。

### 故事 2：五套风格各有气质

**作为**访客
**我希望**有不同气质的风格可选
**以便**找到不刺眼、适合自己的那一套

**验收标准：**
- [ ] 提供 5 套：Arcade、Sunset、暗夜霓虹、糖果马卡龙、雾霾蓝灰。
- [ ] 每套固定一种页面底色，不区分浅色/深色双版本。
- [ ] 雾霾蓝灰为低饱和版本，长时间浏览不刺眼。
- [ ] 旧 cookie 中的 `theme-neon-night` 自动回落到默认主题，不报错。

### 故事 3：切换前能看清楚

**作为**访客
**我希望**在风格下拉里预览每套的配色
**以便**不用逐个切换试错

**验收标准：**
- [ ] 每个选项显示「背景 / 主色 / 强调色」三个色块。
- [ ] 当前选中项有明确选中态。
- [ ] 桌面端为下拉；移动端仍为抽屉内平铺列表。

### 故事 4：切换稳定

**作为**访客
**我希望**切换后刷新仍然保留
**以便**不用每次重选

**验收标准：**
- [ ] 主题写入 cookie + localStorage，刷新后保持。
- [ ] 首帧内联脚本在绘制前挂上主题类名，无"先默认再闪"。
- [ ] 切换不触发整页 JS 重算导致的布局跳动。
- [ ] 首页与 `/mods` 仍是静态路由（`○`）。

## 功能需求

### 核心功能 1：5 套主题变量

在 `src/app/globals.css` 为每套主题定义完整变量（沿用现有 `--neo-*` 体系，补充画布与导航文字变量）：

| 变量 | 用途 |
|---|---|
| `--background` / `--foreground` | 整页底色 / 画布文字 |
| `--neo-canvas` / `--neo-on-canvas` | 首页大背景与画布上的文字 |
| `--neo-panel` / `--neo-ink` | 面板底色 / 面板文字 |
| `--neo-surface` | 次级面板 |
| `--neo-nav` / `--neo-on-nav` | 导航底色 / 导航文字 |
| `--neo-footer` / `--neo-search` | 页脚 / 搜索框 |
| `--neo-accent` / `--neo-secondary` / `--neo-muted` | 强调 / 辅助 / 弱强调 |
| `--border` / `--ring` / `--input` | 组件基础色 |

**5 套配色：**

| 主题 | 画布 | 面板 | 主色 | 辅色 | 强调/弱强调 | 文字 |
|---|---|---|---|---|---|---|
| **Arcade**（默认） | `#EADFCB` 奶油纸 | `#FFF8EC` | `#F26363` 砖红 | `#F2C94C` 琥珀 | `#E7D6BE` 暖沙 | `#1A120B` |
| **Sunset** | `#2A1512` 深酒红 | `#FFF1E4` | `#E8604C` 陶土 | `#E5A93D` 麦金 | `#D8B3A0` 陶粉 | `#FFF1E4`（画布）/ `#2A1510`（面板） |
| **暗夜霓虹** | `#06090C` 近黑 | `#E8F3EC` 雾薄荷 | `#35D97B` 萤绿 | `#3AA6C9` 雾青 | `#C3D3C9` 灰绿 | `#DDF3E4`（画布）/ `#0B1710`（面板） |
| **糖果马卡龙** | `#FBF1F2` 淡粉 | `#FFF9F8` | `#E86A92` 玫红 | `#7FCFB4` 薄荷 | `#F5DFA8` 黄油 | `#2B1B24` |
| **雾霾蓝灰** | `#E3E8EE` 雾霾蓝 | `#FBFCFE` | `#7E97AC` 石板蓝 | `#B7C6D2` 雾灰 | `#DCE4EB` 浅雾 | `#1B242C` |

> 配色规则：每套只保留「一个主色 + 一个辅色 + 低饱和中性色」，避免三种高饱和颜色并列。暗夜霓虹的导航使用深色底 `#0C1418` + 浅色文字，面板保持浅薄荷色，确保黑色描边仍然成立。

### 核心功能 2：风格按钮（下拉 + 三色块）

- 保持现有桌面下拉、移动端平铺。
- 每个选项：主题名 + 一句描述 + 三个色块（背景 / 主色 / 强调色）。
- 当前项选中态（旋转、描边加粗或勾选）。
- 文案全部中文名 + 英文代号（Arcade / Sunset / Night Neon / Macaron / Haze）。

### 核心功能 3：写死颜色替换

在以下范围把硬编码颜色替换为主题变量：

- 头部与导航：`site-header-client.tsx`、`site-search-form.tsx`、`mobile-character-nav.tsx`
- 首页：`home-hero-intro.tsx`、`hero-carousel.tsx`、`mobile-home-intro.tsx`、`mobile-home-feed.tsx`、`mobile-character-drawer.tsx`
- 首页横条：`daily-ticker.tsx`
- 列表页：`mods-toolbar.tsx`、`mod-card.tsx`、`character-sidebar.tsx`、`updates-grid.tsx`
- 页面大底色：首页画布、`/mods` 应用壳、列表页背景

**规则**：只替换"颜色"，不改 `border-4 border-black`、`shadow-[..._#000]` 等 Neo-brutalism 结构特征；`#000` 描边/阴影保持不主题化。

### 边界情况

- 旧 cookie `theme-neon-night`：白名单校验失败 → 回落到 Arcade。
- 深色主题下导航文字切换为浅色；浅色主题保持深色文字。
- 图片上的标题描边与半透明面板不随主题变化（保证可读性）。
- 系统 prefers-reduced-motion 不影响颜色切换。

### 不在范围内

- 不改详情抽屉、每日更新弹窗、页脚的**内部**配色（背景随主题，内部保持原样）。
- 不改首页第二屏（绝区零风格内容区）的内部美术配色，保持其原有视觉。
- 不改绝区零分站的 `zzz-*` 沉浸皮肤机制（独立系统）。
- 不新增字体、不改布局与间距。
- 不做亮度/对比度自定义滑杆。

## 技术约束

### 性能
- 纯 CSS 变量切换，不触发 React 重渲染；不增加客户端 JS 体积。
- 不引入图片/字体等新资源。

### 安全
- 主题值继续走白名单 `isThemeName`，cookie 仅允许 5 个固定值。

### 集成
- `src/lib/theme/constants.ts`：`THEMES` 改为 5 项。
- `src/components/layout/theme-toggle.tsx`：选项与三色块预览。
- `src/app/globals.css`：5 套变量块 + 画布/导航文字变量。
- `src/app/layout.tsx`：首帧内联脚本沿用 `THEMES`，不硬编码。
- 首页画布背景（点阵/网格纹理）改用变量，不新增 JS。

### 技术栈
- Next.js 16 App Router + Tailwind v4 + shadcn/ui；无新依赖。

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 深色主题下文字对比不足 | 中 | 高 | 引入 `--neo-on-canvas` / `--neo-on-nav`，逐项检查 WCAG AA |
| 替换范围大导致漏改 | 中 | 中 | 用 grep 校验 in-scope 文件不再出现旧硬编码色 |
| 浅色画布与原有白色面板对比不足 | 低 | 中 | Arcade/Macaron/Haze 使用深色文字与黑色描边 |
| 主题切换导致闪烁 | 低 | 中 | 沿用 cookie + 首帧内联脚本，不改机制 |
| 首页静态化退化 | 低 | 高 | 不引入 `cookies()` / 服务端读取，主题仍由内联脚本处理 |
