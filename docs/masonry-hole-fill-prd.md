# 产品需求文档：角色分类页瀑布流空洞消除

**版本**：1.1
**日期**：2026-10-19
**作者**：Sarah（产品负责人）
**质量评分**：92/100

---

## 摘要

角色分类页（`/mods?character=…` 与游戏分站的角色筛选）使用绝对定位瀑布流。横屏预览图（宽高比 > 1.1）默认横跨两列，落位取两列中较低一列的底沿，导致**较矮那一列在横屏卡上方空出一大块**。

第一版尝试用「后续卡片回填空洞」解决，实测发现：空洞高度 = 两列底沿之差，而后续卡片高度全部大于残留空洞（实测 174px 的洞 vs 300px+ 的卡片），**物理上填不上**。

最终方案改为**从源头不制造大洞**：横屏卡只有在相邻两列底沿完全齐平时才跨两列，否则这张图按**单列**摆放。这样任何一列都不会出现超过一个正常间距（16px）的垂直空白，卡片顺序也保持与数据顺序一致。

2026-10-19 用户在「全部」视图 6 列下复现了同样的空洞 —— 说明问题不限于角色筛选视图。因此该策略改为**所有瀑布流默认开启**。

---

## 问题陈述

**现状**：`packMasonry` 为每列维护「底部纵坐标」，横屏卡落在两列较低者的底沿，较短列上方形成无法回溯的洞（`masonry-packing.ts` 原实现）。

**用户痛点**：截图中，中间列一张矮横屏卡下方空出近一整张卡的高度，底部横屏卡被推到右列底沿，视觉上像「版面漏了一块」。

**业务影响**：分类页是用户寻找特定角色资源的入口，版面断裂会让人误以为内容缺失或加载失败，降低浏览深度。

---

## 成功指标

- **主指标**：角色分类页任意一列中，相邻卡片之间的垂直空白 ≤ 16px（正常间距），列表底部收尾除外。
- **观感指标**：抽检 5 个角色分类页（桌面 3/5 列、手机 2 列），肉眼无「整块空白」。
- **稳定性指标**：滚动加载下一页时，已有卡片位置不发生移动。
- **顺序指标**：卡片视觉顺序与数据顺序一致（不做跨位置重排）。

## 用户故事与验收标准

### 故事 1：不再出现大洞

**作为**浏览角色分类页的用户
**我希望**卡片之间没有异常空白
**以便**连续浏览时不会看到「版面漏了一块」

**验收标准：**
- [ ] 任意一列中，相邻卡片的垂直间距不超过 1 个 gap（16px）。
- [ ] 唯一的例外是列表底部各列长度不同造成的收尾空白。
- [ ] 图片不裁切、不拉伸，卡片宽高比保持不变。

### 故事 2：所有瀑布流一致

**作为**浏览任意列表的用户
**我希望**所有瀑布流视图都不出现大洞
**以便**无论进入哪个入口，版面都紧凑

**验收标准：**
- [ ] `/mods`（全部视图）生效。
- [ ] `/mods?character=…` 生效。
- [ ] 游戏分站 `/[game]/mods`（含角色筛选）生效。
- [ ] 手机端（2 列）同步生效。

### 故事 3：加载不跳动

**作为**连续下滑的用户
**我希望**加载下一页时已有卡片不动
**以便**阅读位置稳定

**验收标准：**
- [ ] 追加分页数据时，已渲染卡片的 `top` / `column` 保持不变。
- [ ] 卡片顺序始终与数据顺序一致。

## 功能需求

### 核心功能：只在齐平时跨列（alignedSpanOnly）

- **描述**：`packMasonry` 增加 `alignedSpanOnly` 选项。开启后，横屏卡只有在一对相邻列「下一张卡的起点」完全对齐（容差 0.5px）时才横跨两列；否则这张卡按单列卡摆放（`span = 1`）。
- **为什么是「完全对齐」而不是「相差 ≤16px」**：每个列底坐标已含末尾间距，两列底坐标相差 d 时，横屏卡会在较矮那列留下 d + 16px 的洞。要保证洞 ≤16px，必须 d = 0（容差取 0.5px 吸收浮点误差）。
- **用户流程**：进入角色分类 → 横屏卡在齐平的列对处跨列，其余按单列摆 → 列内只有正常间距。
- **边界情况**：
  - 一列时横屏卡不跨列。
  - 比例未加载完时沿用 3/4 兜底，比例到达后重排。
  - 大量同比例图片会让倍列持续齐平，此时横屏卡会正常跨列。
- **错误处理**：非法比例 / 非法容器宽度沿用现有兜底，不产生 NaN 或负坐标。

### 不在范围内
- 不改变横屏卡的跨列阈值（1.1）与卡片尺寸、间距（16px）。
- 不为了填洞而拉伸、裁切图片。
- 不引入第三方瀑布流库。

## 技术约束

### 性能
- 纯函数计算，O(卡片数 × 列数)，与现实现同级；不得引入额外的图片请求或布局测量。

### 安全
- 无用户输入进入计算（仅 id 与图片比例），无新增风险面。

### 集成
- `masonry-packing.ts`：新增 `alignedSpanOnly` 选项。
- `mods-infinite-grid.tsx`：该开关**默认开启**，所有使用该网格的列表自动生效。
- 既有单测必须继续通过；新增对齐跨列单测。

### 技术栈
- TypeScript 纯函数 + Vitest 单测；无新依赖。

### 已验证的取舍
- 横屏卡跨两列与「列内无洞」本质上互斥（两列高度不可控）。
- 选择优先保证无洞：放不下的横屏图按单列显示，视觉上比同列竖屏图矮，但仍完整可读。
