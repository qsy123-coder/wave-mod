## 一、背景与问题

**现状**

- 站内没有任何抽卡/唤取相关能力（`grep 抽卡|唤取|gacha|convene` 在 `src/` 零命中）。
- 玩家想看「我每个卡池垫了多少抽」「平均多少抽出金」「UP 歪了几次」，只能去装桌面工具或第三方网站，其中不少要求上传账号数据。
- 市面同类工具里，[juliy819/wuwa-gacha-tool](https://github.com/juliy819/wuwa-gacha-tool)（TypeScript + Tauri，Apache-2.0）功能最完整，但它是**本地桌面应用**，用户要下载安装。

**问题**

在站内提供一个**打开网页、粘贴官方唤取链接就能看分析**的工具，覆盖基础统计、进阶分析、单个角色/武器的成本档案，并能生成分享图；全过程不保存用户的抽卡数据。

**为什么值得做**

- 抽卡分析是鸣潮玩家的高频需求，能给站内带来新的自然流量入口。
- 与现有 mod 站互补：用户看完 mod 可以顺手看自己的抽卡记录，提升回访。
- 复用成熟开源项目的统计口径，避免自己发明公式导致「算错」。

## 二、目标 / 非目标

### 目标

1. 用户粘贴一条**官方唤取记录链接**，30 秒内看到全量分析结果。
2. 覆盖 13 类卡池（角色/武器精准、常驻、新手、新旅、联动、忆旅），**每个池独立计算垫抽**，不跨池累计。
3. 提供三类分析：
   - **基础**：总抽数、五星数量与概率、平均/中位抽数、每池当前垫抽与 80 抽保底进度。
   - **进阶**：UP 不歪率、歪/不歪次数、五星抽数分布、实际 vs 理论累计出金率、逐抽出金率、按时间的抽卡趋势。
   - **成本档案**：点任意五星，查看逐次获取、前置歪、总抽数与平均成本；角色与专武可合并统计。
4. 生成**可下载的分享图**（浏览器本地 canvas 渲染）。
5. **不落库、不写日志、不缓存**：分析完即弃，分享图不上传服务器。
6. 移植开源项目的统计口径，保留 Apache-2.0 署名。

### 非目标（本期明确不做）

- **不做排行 / 欧非榜**：与「公开访客 + 不落库」冲突，任何聚合都需要存储与匿名上报治理，二期再评估。
- **不做账号体系**，不保存历史记录，不支持多 UID 切换。
- **不做截图 OCR**、不做 JSON 文件导入、不做手动补录（链接抓取已覆盖绝大多数场景）。
- **不打包分发角色/武器图标**：v1 用「名称 + 品质色块 + 首字」展示。~~角色优先复用站内 `characterImageMap` 的头像。~~
  → **2026-11-08 调整**：改为按 `resourceId` 从 COS 读取开源资源包图标，见 4.7。
- 不做云鸣潮/客户端日志自动抓取（需要桌面端能力，网页做不到）。
- 不做个人概率校准倍率（二期）。

## 三、用户故事

### 故事 1：贴链接就出结果

**作为**鸣潮玩家
**我希望**把游戏里「唤取记录」的链接粘进来就能看到完整分析
**以便**不用安装任何软件

**验收标准**

- [ ] 支持 PC 日志链接与云鸣潮链接，参数在 `?` 或 `#/record?` 里都能解析（hash 优先）。
- [ ] 参数做百分号解码，`lang=zh%2DHans` 能正确还原。
- [ ] 链接缺 `player_id` / `record_id` 时给出明确提示，不发上游请求。
- [ ] 13 个卡池全部抓取；单个池失败不影响其他池，结果页列出失败池。
- [ ] 从点击「开始分析」到出结果，正常网络下 ≤ 15 秒。

### 故事 2：每个卡池的垫抽都准

**作为**玩家
**我希望**看到角色池、武器池、常驻池各自垫了多少抽
**以便**决定接下来把资源投到哪个池

**验收标准**

- [ ] 垫抽按池独立，角色池的记录不会影响武器池的进度。
- [ ] 当前垫抽 = 该池最后一条五星之后的抽数。
- [ ] 没有五星的池，显示总抽数并标「≥」（历史可能被截断）。
- [ ] 首个五星区间若历史不完整，显示 `≥N`，不伪装成精确值。
- [ ] 进度条按硬保底 80 抽（新手池 50 抽）计算。

### 故事 3：看懂自己欧不欧

**作为**玩家
**我希望**知道平均多少抽出金、UP 歪了几次、和理论值差多少
**以便**判断这段时期的抽卡表现

**验收标准**

- [ ] 展示总抽数、五星数、五星率、平均五星抽数。
- [ ] 限定角色池展示 50/50 不歪率（歪/不歪次数分开列）。
- [ ] 大保底那一发不计入 50/50 分母（上一发歪、这一发 UP）。
- [ ] 五星抽数分布直方图 + 累计出金率曲线（实际 vs 理论）。
- [ ] 完整区间不足 5 个时，不显示「欧/非」结论，只展示原始数字。

### 故事 4：某个角色我花了多少

**作为**玩家
**我希望**点某个五星角色，看到我每次抽到它花了多少、前置有没有歪
**以便**复盘单个角色/专武的成本

**验收标准**

- [ ] 点击五星进入获取档案，列出每次获取的时间、当次抽数、是否前置歪。
- [ ] 汇总显示总抽数、平均抽数；有专武映射时，角色与专武可分开或合并统计。
- [ ] 首个获取若历史不完整，成本显示 `≥`。
- [ ] 未获取的角色/武器显示「未获取」，不显示 0。

### 故事 5：分享结果不泄露隐私

**作为**玩家
**我希望**生成一张图发给朋友，但不想暴露完整 UID
**以便**分享战绩又不泄露账号信息

**验收标准**

- [ ] 分享图在浏览器本地生成，不上传服务器。
- [ ] UID 默认打码（如 `106****288`），可手动切换显示完整 UID。
- [ ] 分享图包含：总抽数、五星率、平均抽数、不歪率、各池垫抽。
- [ ] 生成失败时给出提示，不影响页面其他功能。

## 四、方案设计

### 4.1 形态与路由

| 项 | 决定 |
| --- | --- |
| 形态 | 站内网页工具（服务端代理抓取） |
| 主站域名 | `https://go.sunnyrose.xyz`（`wave-mod.top` 已于 2026-10-16 整站关闭） |
| 路由 | `/gacha`，放在 `(site)` 路由组下，复用现有站点头部与布局 |
| 页面类型 | Server Component 外壳 + Client Component 工作台 |
| 入口 | 顶部导航「更多」下拉加「抽卡分析」；首页可选加一张入口卡 |

**为什么不用 `/tools/gacha`**：`/tools/blur` 是站长内部工具（`robots: noindex`，无站点头部）。抽卡分析是面向公众的功能页，应该是一级页面，能进 sitemap、能被分享。

### 4.2 复用策略：移植逻辑，重写 UI

选定**移植 `juliy819/wuwa-gacha-tool` 的分析逻辑**，不 fork 它的前端 SPA。

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 移植分析逻辑 | 口径与成熟工具一致；纯 TS 可单测；UI 与站内统一 | 需要读懂并重写 Rust 侧算法 | ✅ 采用 |
| fork 前端 SPA | 省 UI 工期 | 依赖 Tauri/SQLite/本地文件系统；风格不一致；上游更新难合并 | ❌ |
| 只参考数据模型 | 最干净 | 保底、歪、UP 周期等细节容易写错 | ❌ |

**许可**：源项目 Apache-2.0。移植属于衍生作品，必须：
- 在 `src/features/gacha/lib/NOTICE.md` 保留原项目版权与 Apache-2.0 许可声明；
- 在文件头注明「移植自 juliy819/wuwa-gacha-tool 的 `src-tauri/src/gacha/parser.rs`」。

### 4.3 数据抓取链路

```
用户粘贴链接
   ↓ 前端只做基本格式校验
POST /api/gacha/fetch { url }          （Vercel hkg1）
   ↓ 服务端解析 query + hash（hash 优先），只取参数，不请求用户给的域名
   ↓ 按 player_id 选上游；生产环境走香港 nginx 代理
POST https://go.sunnyrose.xyz/__gacha/query   （香港 nginx，带 X-Wavemod-Key）
   ↓ nginx 固定转发到官方接口
13 次 POST /gacha/record/query（并发 3–4，单池 8s 超时）
   ↓ 归一化 + 按池分组
返回 { uid, region, pools, records, warnings }
   ↓ 浏览器内存中计算统计
页面渲染（不落库、不写日志）
```

**为什么绕香港**：2026-11-08 实测，官方接口对 Vercel 出口完全不响应（直连生产函数 25s 超时），
同一请求从香港机 1.3–2.6s 就能拿到响应（含 `code=-1`）。因此生产环境通过
`GACHA_PROXY_URL` + `GACHA_PROXY_KEY` 走香港 nginx 的 `/__gacha/query`；
本地开发不配这两个变量时仍直连官方接口。nginx 侧只暴露固定上游、固定方法，
无 key 或 key 不符直接 403。

**上游接口（固定白名单，杜绝 SSRF）**

- 国服：`https://gmserver-api.aki-game2.com/gacha/record/query`
- 国际服：`https://gmserver-api.aki-game2.net/gacha/record/query`
- 请求体：

```json
{
  "playerId": "<player_id>",
  "recordId": "<record_id>",
  "cardPoolId": "<resources_id>",
  "serverId": "<svr_id>",
  "languageCode": "<lang，默认 zh-Hans>",
  "cardPoolType": "1"
}
```

- 服务器区域：`player_id` 以 `1` 开头 → 国服，否则国际服（与源项目一致）。
- `record_id` 有效期约 1 小时；失效时上游返回 `code: -1`。

**为什么不在浏览器直连**：上游无 CORS 头；且直连会暴露 `record_id` 给第三方页面脚本。服务端代理 + `Cache-Control: no-store` 是唯一可行且不落地的方案。

### 4.4 分析口径（必须与源项目一致）

**卡池映射**

| ID | API 中文名 | 展示名 | 分组 |
| --- | --- | --- | --- |
| 1 | 角色精准调谐 | 角色活动唤取 | UP 角色池 |
| 2 | 武器精准调谐 | 武器活动唤取 | UP 武器池 |
| 3 | 角色常驻调谐 | 角色常驻唤取 | 常驻角色池 |
| 4 | 武器常驻调谐 | 武器常驻唤取 | 常驻武器池 |
| 5 | 新手调谐 | 新手唤取 | 新手池（硬保底 50） |
| 6 / 7 | 新手自选调谐 | 新手自选唤取 | 新手池 |
| 8 | 角色新旅调谐 | 角色新旅唤取 | UP 角色池 |
| 9 | 武器新旅调谐 | 武器新旅唤取 | UP 武器池 |
| 10 | 角色联动调谐 | 角色联动唤取 | UP 角色池 |
| 11 | 武器联动调谐 | 武器联动唤取 | UP 武器池 |
| 12 | 角色忆旅调谐 | 角色忆旅唤取 | 忆旅角色池 |
| 13 | 武器忆旅调谐 | 武器忆旅唤取 | 忆旅武器池 |

**基础规则**

- 排序：`time` 升序；同一时间戳的十连，按 API 原始顺序**倒序**作为 tie-break（API 返回新→旧）。
- 垫抽**按池独立**，即使两个池的记录在时间上交错也不互相影响。
- 五星区间 = 上一次五星之后到本次五星的抽数（**含本次**）。
- 首个五星区间若历史被截断 → `isLowerBound = true`，展示 `≥N`。
- 当前垫抽 = 该池最后一条五星之后的抽数；该池无五星则等于总抽数，同样标 `≥`。
- 平均 / 中位数 / 最大 / 最小**只用完整区间**。

**歪与 50/50**

- 常驻五星角色 ID：`[1104, 1203, 1301, 1405, 1503]`（维里奈、卡卡罗、鉴心、凌阳、安可）。
- 常驻五星武器 ID：`[21010015, 21020015, 21030015, 21040015, 21050015, 21010045, 21020045, 21030045, 21040045, 21050045]`。
- `isOffRate = qualityLevel === 5 && resourceType === "role" && 限定角色池(1/8/10/12) && resourceId ∈ 常驻五星角色`。
- 50/50 分母：限定角色池的五星角色结果；**上一发是歪、本发是 UP 的「大保底」不计入分母**。
- UP 周期成本：从上一个 UP（或歪）结束开始，到本次 UP 出金为止的全部抽数，**含前置歪**；理论期望 81.15 抽。

**理论模型（分段软保底）**

| 抽数 | 单抽出金率 |
| --- | --- |
| 1–65 | 0.8% |
| 66–70 | 0.8% + 4% × (n − 65) |
| 71–75 | 上一档 + 8% / 抽 |
| 76–78 | 上一档 + 10% / 抽 |
| 79 | 100%（必出） |
| 80 | 硬保底 |

- 理论期望：普通五星 **54.1 抽**；UP 成本 **81.15 抽**。
- 新手池（type 5）硬保底 50，**不套用软保底曲线**。
- 理论中位数由上述模型对 50% 累计概率求阈值得到（源项目 `theoreticalThreshold(0.5)`）。

**概率曲线**

- 「逐抽出金率」：规则基线曲线；样本足够时可选叠加个人校准倍率（二期）。
- 「累计出金率」：用户自身完整区间的经验分布（第 N 抽前出金的累计占比），与历史中位数一起展示。

### 4.5 分享图

- 纯浏览器 canvas（`<canvas>` + `toBlob`）绘制，不引入图表库、不上传。
- 尺寸 1080×1350（适配手机分享）。
- 内容：站名、UID（打码）、时间范围、总抽数、五星率、平均抽数、不歪率、各池垫抽、尾部小字「数据仅在本机生成」。
- 中文字体用系统字体栈，避免打包字体文件。

### 4.6 为什么不做排行

用户明确选择「不落库、不做排行」。技术上排行需要：明细或聚合数据入库 → 匿名身份 → 防刷 → 数据删除入口 → 合规声明。这与「公开访客、分析完即弃」的承诺直接冲突，因此整块移出本期。

### 4.7 角色 / 武器素材

**问题**：站内 `characterImageMap` 按角色名匹配，官方新增的形态名（`漂泊者·衍射`、`漂泊者·气动`、`莉莉`、`陆·赫斯` 等）不在表里，五星账本会退回首字色块。

**方案**：改用开源项目 `juliy819/wuwa-gacha-tool-resources` 的资源包（nanoka.cc 快照），文件按 `resourceId` 命名：

```
COS: /gacha-res/icons/<resourceId>.webp       ← 187 个，覆盖角色与武器
COS: /gacha-res/portraits/<resourceId>.webp   ← 65 个，备用
```

- 上传脚本：`scripts/upload-gacha-resources-to-cos.mjs --dir=<解压目录>`
- 页面取图顺序：资源包（按 ID）→ 站内 `characterImageMap`（按名）→ 品质色块 + 首字。
- 不再依赖角色名，官方新增角色只要更新资源包并重跑脚本即可。
- COS 已配置 CORS（允许 `go.sunnyrose.xyz`），后续可把图标画进分享图。
- 素材版权与归属见 `src/features/gacha/lib/NOTICE.md`。

### 5.2 接口契约

`POST /api/gacha/fetch`

请求：

```ts
{ url: string } // 20–2048 字符
```

响应（200）：

```ts
type FetchResponse = {
  uid: string;                 // 原样返回，前端默认打码
  region: "cn" | "global";
  fetchedAt: string;           // ISO
  records: GachaRecord[];
  failedPools: { poolType: string; message: string }[];
};

type GachaRecord = {
  poolType: string;            // "1".."13"
  poolName: string;            // API 返回的中文池名
  resourceId: number;
  qualityLevel: 3 | 4 | 5;
  resourceType: "role" | "weapon";
  name: string;
  time: string;                // "YYYY-MM-DD HH:mm:ss"
};
```

错误（400/422/502/504）：

```ts
{ error: "invalid_link" | "expired_link" | "upstream_timeout" | "upstream_error" | "rate_limited",
  message: string }
```

- `Cache-Control: no-store`，不写日志，不落库。
- 单 IP 限流 10 次/分钟（进程内滑动窗口，Vercel 多实例下为近似值）。

### 5.3 安全约束

1. **禁止把用户输入的 URL 直接请求出去**——只解析参数，出站 URL 来自固定常量。
2. 校验 `player_id` 为数字（≤ 20 位）、`record_id` 为 32 位十六进制，避免把任意字符串转发给上游。
3. 请求体大小上限 4 KB；URL 长度上限 2048。
4. 不记录 `record_id`、`player_id` 到任何日志或错误上报。
5. 上游响应先做结构校验（Zod），异常结构返回 `upstream_error`，不把原始 JSON 透传给前端。

## 六、边界与异常

| 场景 | 表现 |
| --- | --- |
| 链接格式不对 | 输入框下方红字「这不是有效的唤取记录链接」，不发请求 |
| 缺 `player_id` / `record_id` | 同上，附带「怎么获取链接」折叠引导 |
| `record_id` 过期（code -1） | 「链接已失效（约 1 小时有效），请重新从游戏内复制」 |
| 部分卡池失败 | 展示已成功的池 + 顶部黄条列出失败池；不阻塞 |
| 全部卡池失败 | 整页错误态 + 重试按钮 |
| 上游超时 | 25 秒总预算，超时返回 `upstream_timeout`，提示稍后重试 |
| 无任何记录 | 空态：「这个账号还没有唤取记录」+ 获取链接引导 |
| 只有 1 个五星 | 不显示欧非结论，只显示原始抽数并标「样本不足」 |
| 首个区间不完整 | 所有相关数字前缀 `≥`，hover 说明官方只保留约 6 个月 |
| 同一时间戳多条记录 | 按 API 原始顺序倒序，保证十连顺序稳定 |
| 分享图渲染失败 | toast 提示，页面其他功能不受影响 |
| 限流 | 429 + 「请求太频繁，请 1 分钟后再试」 |
| JS 关闭 | Server Component 外壳仍可打开，显示「需要启用 JavaScript」 |

## 七、隐私与合规

- 页面固定文案：「唤取链接包含一次性凭证，仅用于本次分析；我们不保存你的 UID、抽卡记录或链接。」
- 服务端不写数据库、不写文件、不接第三方统计；`/api/gacha/fetch` 的响应头 `Cache-Control: no-store`。
- UID 默认打码展示；完整 UID 只保存在当前页面内存。
- 分享图在浏览器生成，不上传。
- 不抓取、不存储任何账号密码或登录态。

## 十一、风险与回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 官方接口非公开，可能改字段/限流/封 IP | 功能不可用 | 代理层可切到香港 nginx 出口；错误码可观测；页面给明确提示；不影响主站 |
| `record_id` 仅约 1 小时有效 | 用户粘贴旧链接失败 | 文案明确写出有效期 + 获取引导 |
| 官方只保留约 6 个月记录 | 首个区间偏小 | 首区间标 `≥`，页面说明 |
| Vercel 函数时长不足 | 13 个上游请求超时 | 并发 3–4 + `maxDuration = 60` + 25 秒总预算 |
| 上游偶发返回非 JSON | 页面崩 | Zod 结构校验 + 降级错误态 |
| Apache-2.0 署名遗漏 | 许可风险 | `NOTICE.md` + 文件头注明来源，纳入 code review 检查项 |
| 角色/武器图标版权 | 法务风险 | v1 不打包图标，用文字 + 色块；角色头像仅复用站内已有资源 |

**回滚**：本功能不写数据库、不改现有表、不接管任何路由。下线只需删除 `/gacha` 路由与 `/api/gacha`，主站零影响。
