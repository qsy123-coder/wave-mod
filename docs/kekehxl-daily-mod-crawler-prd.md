## 一、执行摘要

**可可站**（kekehxl.top / kekehxl.org）是《鸣潮》Mod 的搬运站点，采用 **不定时更新** 模式 —— 早、中、晚都可能随时新增 Mod。目前用户需要人工反复刷新网站、逐个点开商品页、手动记录夸克网盘链接，再整理进 `A_每日更新/W-日期/` 文件夹，耗时且容易漏掉更新。

本系统将这一流程完全自动化：在**首尔云服务器**上 7×24 轮询站点 API，一旦发现新 Mod 立即通过**微信（Server酱）推送**，同时把结构化元数据写入按日期分类的 CSV，并定时回传到本地原有文件夹。用户从"被动盯站"变为"更新主动找人"。

**核心价值**：新 Mod 从发布到用户手机收到链接，延迟 **≤10 分钟**；彻底消除人工刷新与手工记录。

---

## 二、问题陈述

**现状**：站点不定时更新，用户需手动刷新网站 → 打开商品页 → 复制夸克链接与提取码 → 手工填进 CSV → 归档到日期文件夹。更新分散在全天，用户无法持续盯站，必然漏更新。

**方案**：云端常驻程序轮询站点 WooCommerce REST API，自动提取夸克链接/提取码/发布日期等元数据，即时推送 + 自动归档。

**业务影响**：
- 人工操作时间从每天约 15–30 分钟降至 **0**
- 漏更新率从"必然发生"降至 **0**（基于已见 ID 差集检测）
- 拿到链接的延迟从"数小时～一整天"降至 **≤10 分钟**

## 六、功能需求

### 核心功能

#### 功能 1：登录与凭证管理（`login.py`）
- **描述**：**纯 HTTP**（`requests`/`httpx`）POST 站点密码，保存会话 Cookie。**无需浏览器。**
- **访问链**（已在首尔服务器实测）：
  1. `GET https://kekehxl.org/` → `302` → `/?password-protected=login&redirect_to=...`（**无验证码**）
  2. `POST` 表单字段：`password_protected_pwd=kekehxl`、`password_protected_cookie_test=1`、`password-protected=login`、`redirect_to=https://kekehxl.org/`
  3. 站点密码：`kekehxl`（存 `config.ini`）
- **产出 Cookie**：
  - `bid_1_password_protected_auth` —— 密码凭证，内嵌过期时间戳，约 **19 天**
  - `wordpress_test_cookie` 等辅助 cookie
- **关键结论**：验证码 `sgcaptcha` 只被**香港机房 IP（本地代理出口）**触发；**首尔服务器出口 IP 干净，全程无验证码**，故无需 Playwright/Chrome/xvfb。
- **失效处理**：API 返回 401/202 或出现 `sgcaptcha` 时，自动用密码重新登录并重试；仍失败则微信告警。

#### 功能 2：增量轮询与差集检测（`poller.py`）
- **描述**：常驻循环，每 10 分钟执行一次。
- **数据源**（已实测可用，带 Cookie 时纯 HTTP 即可，无需浏览器）：
  ```
  GET https://kekehxl.org/wp-json/wp/v2/product
      ?product_cat=21            # 21 = 鸣潮Mod
      &orderby=date&order=desc
      &per_page=100
      &after=<上次成功时间>
  ```
- **检测逻辑**：
  1. 拉取 `product_cat=21` 的商品
  2. 与 `state.json` 中 `seen_ids` 求差集 → 得到新 Mod
  3. 首次运行：把当日已有 Mod 作为基线全部归档，发一条汇总推送
  4. 更新 `state.json`（`seen_ids`、`last_poll_at`）
- **边界与错误处理**：

  | 场景 | 处理 |
  |---|---|
  | Cookie 失效（HTTP 202/403） | 触发 `login.py` 重登，成功后续跑；失败发告警 |
  | 验证码升级导致登录失败 | 重试 3 次，仍失败 → 微信告警"需人工介入" |
  | API 路径变更（404/结构异常） | 记录日志 + 微信告警，不静默失败 |
  | 网络/代理抖动 | 指数退避重试 3 次 |
  | 同一 Mod 被编辑 | 以 `modified` 字段识别，可选标记"已更新"状态 |
  | 站点删除某 Mod | 不删本地已归档记录 |

#### 功能 3：元数据解析（`parser.py`）
- **描述**：从商品 JSON 的 `excerpt.rendered`（HTML）抽取网盘信息。
- **抽取规则**（已实测验证）：
  - 夸克盘链接：正则 `pan\.quark\.cn/s/[\w]+`
  - 提取码：从 `提取码 ：xxxx` 文本抽取（站点当前统一为 `keke`）
  - 解压码：`解压码 ：kekehxl`（仅记录，不入主表）
- **实测样例**：
  ```json
  {
    "id": 17408,
    "date": "2026-10-10T11:22:30",
    "title": { "rendered": "心(含大招)-时之执政" },
    "link": "https://kekehxl.org/product/心(含大招)-时之执政/",
    "excerpt": "... 夸克盘： 点击获取 → https://pan.quark.cn/s/b78091c13d26 ... 提取码 ：keke",
    "product_cat": [21],
    "product_tag": [194]
  }
  ```

#### 功能 4：归档输出（`writer.py`）
- **每日 CSV**：`out/W-YYYY.M.D.csv`（日期取站点 `date` 字段的日期部分）
- **全量总表**：`out/all_mods.csv`（追加去重，永不删除历史行）
- **CSV 字段**：

  | 列名 | 来源 | 说明 |
  |---|---|---|
  | 日期 | `date` | 发布日期 YYYY-MM-DD |
  | mod名称 | `title.rendered` | |
  | 夸克链接 | 正则抽取 | |
  | 提取码 | 正则抽取 | |
  | 分类 | `product_cat` | 固定为"鸣潮Mod" |
  | 角色标签 | `product_tag` | 如"心""坎特蕾拉" |
  | 网站页面链接 | `link` | |
  | product_id | `id` | 去重键 |
  | 首次发现时间 | 程序生成 | 便于排查延迟 |

- **说明**：按用户要求**不含**"作者"列（站点无此字段）、**不含**百度盘/MEGA盘列。

#### 功能 5：即时通知（`notify.py`）
- **Server酱（微信）**：`POST https://sctapi.ftqq.com/<SendKey>.send`，`title`=新 Mod 摘要，`desp`=Markdown 明细（含可点链接）
- **本地桌面弹窗**：由本地同步脚本触发 Windows toast
- **无新内容时静默**，不发空推送

#### 功能 6：本地回传（本地侧 `sync.bat` + 计划任务）
- **描述**：本地 Windows 计划任务定时 `scp`/`rsync` 从服务器拉取 `out/` 到 `A_每日更新/`
- **冲突策略**：以云端为准，但保留本地更新版本（按 mtime 比较）
- **附加**：拉取后比对，若有新行则弹桌面通知

### 不在本次范围（Out of Scope）

- ❌ 自动下载预览图
- ❌ 百度盘 / MEGA 盘链接采集

## 七、技术约束

### 性能
- 轮询周期 10 分钟，每次 1 个 API 请求（`per_page=100`），对站点压力可忽略
- 单次轮询耗时目标 < 5 秒（不含重登）
- 首次登录（含两次验证）实测约 12–60 秒，视验证码耗时

### 安全
- **站点密码、Cookie、Server酱 SendKey 一律存入服务器 `config.ini`，权限 600，禁止提交进代码仓库**
- Cookie 文件等同账号凭证，不外传
- 仅访问用户有权访问的站点内容，遵守站点使用约定，请求频率控制在每 10 分钟 1 次

### 集成
- **目标站点**：kekehxl.org（已确认 WordPress + WooCommerce + Elementor Pro）
- **代理**：本地 `127.0.0.1:7897`（Clash Verge，实测可用）；服务器侧优先直连，若受限则配置同一代理
- **推送**：Server酱（`sctapi.ftqq.com`）
- **回调**：本地 `scp`/`rsync` over SSH

### 技术栈
- **语言**：Python 3.10（服务器 Ubuntu 22.04 已具备 3.10.12）
- **关键库**：`requests`（HTTP）、`re`/`html`（解析）、标准库 `csv`/`json`/`configparser`
- **服务器**：腾讯云首尔服务器（Ubuntu 22.04，2 核 / 1.9G / 35G 可用），**无需浏览器**
- **本地**：Windows 11（仅用于 `scp` 回传）

### 关键实测结论（架构依据）
| 结论 | 证据 |
|---|---|
| **首尔 IP 不触发验证码** | 服务器上 `GET /` → 302 → 密码页，仅 1 跳，无 `sgcaptcha` |
| **纯 HTTP 登录可用** | `POST password_protected_pwd=kekehxl` → 200 → 跳回首页 |
| **Cookie 可免浏览器调 API** | 带 Cookie `GET /wp-json/wp/v2/product?product_cat=21` → HTTP 200 + 真实 JSON |
| REST API 结构完整 | 返回 `id`/`date`/`title`/`excerpt`(含夸克链接)/`link`/`product_tag` |
| 按日期过滤有效 | `after=2026-10-10T00:00:00` → 8 条；`2026-10-09` → 16 条 |
| 验证码仅由香港机房 IP 触发 | 本地代理（HK 出口）→ 202 `sgcaptcha`；首尔 → 无 |
| 站点时区为 UTC | `date` 与 `date_gmt` 完全相同；服务器本地时区为 CST(UTC+8) |

## 八、MVP 范围与分期

### 第一期：MVP（必须）
1. `login.py` —— 纯 HTTP 登录 + Cookie 保存与复用
2. `poller.py` —— 轮询 + 差集检测 + 状态存储（单次可跑模式）
3. `parser.py` + `storage.py` —— 解析出夸克链接，写当日 CSV + 总表
4. `notify.py` —— Server酱 推送
5. **在服务器上直接验证**（跳过本地转测，因服务器环境即生产环境）

**MVP 定义**：服务器上能一键跑通"登录 → 轮询 → 解析 → 写 CSV → 微信推送"，且无重复无漏。

### 第二期：自动化
6. `systemd` 常驻守护，每 10 分钟轮询
7. Cookie 过期自动重登 + 失败告警
8. 本地 `scp` 定时回传 + 桌面通知

### 第三期：增强（后续）
9. 每日终检对账（站点当日条数 vs 归档条数）自动告警
10. 支持终末地 Mod 分区（开关配置）
11. 可选导出 XLSX（对齐现有 `分享结果导出` 格式）

## 九、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| 站点开始对首尔 IP 也发验证码 | 低 | 高 | 检测到 `sgcaptcha` 立即告警；届时再引入 Playwright+xvfb 方案 |
| 站点 API 路径/字段变更 | 中 | 高 | 结构校验 + 异常告警，不静默失败；解析层集中便于修改 |
| Cookie 过期导致漏采集 | 中 | 中 | 轮询遇 401/202 立即重登；重登窗口内的 Mod 依靠 `after` 时间补水 |
| 站点封禁服务器 IP | 低 | 高 | 控制请求频率（10 分钟 1 次）；必要时换出口 |
| 服务器被墙/网络抖动 | 低 | 中 | 重试 + 告警；Seoul 节点直连已验证可用 |
| 服务器上 nginx 现有站点受影响 | 低 | 高 | 本项目仅新增独立 systemd 服务与目录，**不改动 nginx 任何配置** |
| 本地回传遗漏（长期关机） | 中 | 低 | 云端保留全量数据，开机后按时间补齐 |

## 附录 B：待确认假设

以下为本 PRD 基于实测与常识做出的假设，请确认或纠正：

1. **CSV 列**：以"角色标签"替代已删除的"作者"列（免费且有用）。若不要，可去掉。

5. **桌面通知**：由本地同步脚本触发，仅在电脑开机时可见（云端无法直接弹本地窗口）。
