# 项目技术栈总览

本文档基于当前项目实际代码、配置文件、依赖清单和数据库脚本扫描生成，覆盖范围包括 `package.json`、`next.config.ts`、`tsconfig.json`、`eslint.config.mjs`、`postcss.config.mjs`、`components.json`、`src/` 源码目录与 `supabase/` SQL 脚本。

## 1. 核心框架

- Next.js 版本：`16.2.3`
  - 使用位置：`package.json`、`src/app/`。
  - 使用方式：采用 App Router，路由集中在 `src/app/` 下，包括页面路由、Route Handlers、布局和 Proxy/Middleware。
  - 构建方式：`next build`，构建输出显示使用 Turbopack。
  - 阶段 3 已启用 `reactCompiler: true` 与 `cacheComponents: true`，构建输出显示 `Cache Components enabled`。
  - 启用 Cache Components 后，多个页面以 Partial Prerender 形式输出，动态内容通过 Suspense 边界服务端流式补齐。
- React 版本：`19.2.4`
  - 使用位置：全项目 `.tsx` 组件。
  - 使用方式：服务端组件为主，交互组件通过 `"use client"` 显式声明。
- React DOM 版本：`19.2.4`
- TypeScript 版本：`5.9.3`
  - 配置文件：`tsconfig.json`。
  - 使用方式：项目源码以 `.ts` / `.tsx` 为主，开启 `strict: true`、`noEmit: true`、`isolatedModules: true`、`moduleResolution: bundler`。
  - 路径别名：`@/*` 指向 `./src/*`。
- 其他核心运行特性：
  - Next.js Metadata API：`src/app/layout.tsx` 中定义站点标题与描述。
  - Route Handlers：`src/app/api/**/route.ts`。
  - Proxy/Middleware：`src/proxy.ts`，用于保护 `/admin/:path*`。
  - Server Actions：`src/actions/**`，用于认证、后台 MOD 管理、收藏、点赞、评论、评分等服务端变更操作。

## 3. 状态管理

- 客户端状态：
  - React 内置状态：`useState`、`useEffect`、`useMemo`、`useCallback`、`useTransition`、`useActionState`。
  - 使用位置：上传组件、登录表单、主题切换、轮播、详情页收藏/点赞/评分、评论面板、无限列表等。
- 服务端/全局状态：
  - Supabase Auth Session：通过 `@supabase/ssr` 的 Cookie 集成在服务端读取用户状态。
  - React Query 全局 Provider：`src/components/layout/client-providers.tsx` 中创建 `QueryClientProvider`。
  - 自定义主题状态：`src/components/layout/theme-provider.tsx` 使用 React Context + `localStorage` 管理主题。
- 数据获取方式：
  - Server Components：主要页面在服务端直接调用 `src/lib/mods.ts` 中的数据函数，例如首页、MOD 列表、详情页、后台页面。
  - Server Actions：`src/actions/**` 用于变更数据后调用 `revalidatePath`。
  - TanStack Query：
    - 版本：`@tanstack/react-query@5.99.0`。
    - 使用位置：`src/components/layout/client-providers.tsx`、`src/components/features/mods/detail/comments-panel.tsx`、`src/components/features/mods/list/mods-infinite-grid.tsx`。
    - 用途：评论区分页加载和 MOD 列表无限加载，统一使用 `useInfiniteQuery`。
  - 阶段 2 已移除 SWR：
    - 原 `src/components/features/mods/list/mods-infinite-grid.tsx` 已从 `useSWRInfinite` 迁移到 TanStack Query。
    - `swr` npm 包已卸载，客户端数据缓存策略统一到 TanStack Query。
  - Fetch API：客户端组件调用 `/api/mods`、`/api/mods/[id]/comments`、`/api/mods/[id]/download`、`/api/mods/[id]/view`、`/api/oss/sign`。

## 4. 数据库与 ORM

- 数据库类型：PostgreSQL，由 Supabase 提供。
  - SQL 脚本位置：`supabase/schema.sql`、`supabase/add_downloads.sql`、`supabase/add_likes.sql`、`supabase/add_ratings.sql`、`supabase/backfill_profiles.sql`。
- ORM / 查询库：未使用传统 ORM。
  - 没有 Prisma、Drizzle、TypeORM 等依赖或配置。
  - 数据访问通过 Supabase JavaScript Client 查询 PostgreSQL。
- 数据库客户端：
  - `@supabase/supabase-js@2.103.0`。
    - 使用位置：`src/lib/supabase/admin.ts`。
    - 用途：服务端 Service Role 管理客户端，用于后台管理、插入/更新/删除等需要管理员权限的操作。
  - `@supabase/ssr@0.10.2`。
    - 使用位置：`src/lib/supabase/server.ts`、`src/lib/supabase/client.ts`、`src/proxy.ts`。
    - 用途：Server Components、Route Handlers、Proxy 中的 Cookie Session 集成。
- 数据表设计：
  - `profiles`：用户资料与角色。
  - `mods`：MOD 主表，包含标题、角色、版本、描述、图片、视频、下载链接、标签、统计字段、发布状态等。
  - `favorites`：收藏关系。
  - `likes`：点赞关系。
  - `comments`：评论。
  - `ratings`：评分。
- 数据库安全：
  - 启用 Row Level Security。
  - 使用 `public.is_admin()` 判断管理员。
  - 针对公开读取、管理员写入、用户自己的收藏/评论/评分等定义 RLS Policy。

## 5. 认证与授权

- 认证方案：Supabase Auth。
  - 使用位置：`src/actions/auth/auth-actions.ts`、`src/app/auth/callback/route.ts`、`src/app/auth/login/page.tsx`、`src/components/features/auth/login-form.tsx`。
  - 当前登录方式：邮箱 OTP / Magic Link，调用 `supabase.auth.signInWithOtp()`。
  - 阶段 16 已完成登录页中国化改造：产品表达改为“邮箱验证码登录”优先，增加支持邮箱提示、发送成功状态、重新发送倒计时、管理员邮箱说明和更贴近中国用户的中文文案。
  - 阶段 17 已完成微信登录最小入口与配置边界：Supabase Auth 当前官方 Provider 列表不包含微信，登录页仅在普通用户模式展示“微信快捷登录”，通过 `WECHAT_AUTH_BRIDGE_URL` 指向后续自定义微信认证桥接；未配置时返回明确提示，不伪造可用登录。
  - 阶段 18 已完成手机号验证码登录最小入口与配置边界：普通用户登录页新增手机号验证码区域，默认由 `ENABLE_SUPABASE_PHONE_OTP` 控制关闭；启用前需配置 Supabase Phone OTP、短信服务商、短信模板和防刷策略。
  - 回调处理：`src/app/auth/callback/route.ts` 使用 `exchangeCodeForSession()` 创建会话。
  - 中国用户登录升级方案已单独沉淀到 `docs/中国用户登录方案文档.md`：推荐继续以 Supabase Auth 作为统一身份中心，按邮箱验证码、微信、手机号、QQ、账号绑定的顺序分阶段建设。
- 授权方案：
  - 管理员判断：基于环境变量 `ADMIN_EMAIL` 与当前用户 email 比对。
  - 后台保护：
    - 页面级：`requireAdminUser()`。
    - Proxy 级：`src/proxy.ts` 匹配 `/admin/:path*`，非管理员跳转登录。
  - 普通用户保护：`requireAuthUser()` 用于收藏页等需要登录的页面。
- Session 管理：
  - `@supabase/ssr` 通过 Next.js cookies 在 Server Components、Route Handlers 和 Proxy 中读取/写入会话。

## 10. 架构特点

- 是否使用 App Router：是。
  - 路由目录：`src/app/`。
  - 页面分组：`src/app/(site)/` 用于公开站点，`src/app/admin/` 用于后台，`src/app/auth/` 用于认证，`src/app/api/` 用于 API Route Handlers。
- Server Components 使用程度：较高。
  - 默认页面组件大多为 Server Components，例如首页、MOD 列表页、详情页、后台页面。
  - 仅交互组件使用 `"use client"`，例如上传组件、登录表单、轮播、主题切换、评论面板、收藏/点赞/评分按钮等。

  - 目录：`src/actions/`。
  - 分类：`admin`、`auth`、`mods`。
  - 用途：认证登录/退出、管理员上传/编辑/删除/发布 MOD、用户收藏/点赞/评分/评论等。
- 缓存策略：
  - 阶段 3 已在 `next.config.ts` 启用 `reactCompiler: true` 与 `cacheComponents: true`。
  - React Compiler 依赖：`babel-plugin-react-compiler`，作为 devDependency 安装。
  - 构建输出显示 `Cache Components enabled`，并将 `/`、`/mods`、`/mods/[id]`、`/favorites`、`/auth/login`、后台页面等输出为 Partial Prerender。
  - Server Actions 中使用 `revalidatePath()` 触发路径级重新验证。
  - React Query 默认配置：`staleTime: 30_000`，关闭窗口聚焦自动刷新。
  - TanStack Query 用于客户端无限加载和评论分页；列表页通过 `initialData` 接入 Server Components 首屏数据，避免首屏重复请求。
  - 阶段 3 为动态数据读取补充 Suspense 边界：公开首页角色区、MOD 列表筛选区、MOD 详情 `params`、收藏页用户数据、后台布局用户信息、后台页面数据、登录页 `searchParams`。
  - 阶段 4 已开始拆分公开数据与用户态数据：`getPublicModBaseById()` 只读取公开 MOD 基础详情，`getViewerModState()` 只读取当前用户的收藏、点赞、评分状态，详情页再组合两者。
  - 阶段 5 已新增 `createPublicReadClient()`，使用 Supabase anon key 创建不读取 cookies 的服务端公开只读客户端。
  - 阶段 5 已将公开角色、公开 MOD 列表、公开 MOD 详情基础信息、公开评论分页切换到 `createPublicReadClient()`，减少公开查询对 request cookies 的隐式依赖。
  - `getWeeklyHotMods()` 已移除构建期 `Date.now()`，改为基于已查询 MOD 的最新 `createdAt` 派生 7 天热度窗口。
  - 阶段 6 已在低风险公开只读函数中试点 `"use cache"`：`getAvailableCharacters()`、`getPublicMods()`、`getPublicModBaseById()`。
  - 阶段 6 暂未缓存评论分页、用户态状态、收藏页和后台认证数据，避免影响实时性或产生用户态缓存污染。
  - 构建输出显示首页 `/` 已变为静态路由，并出现默认 `Revalidate 15m / Expire 1y`。
  - 阶段 7 已补充 `cacheTag` / `cacheLife` 与统一缓存失效封装：`mods:characters`、`mods:list`、`mods:detail:{id}`。
  - 阶段 7 后构建输出显示首页 `/` 缓存策略为 `Revalidate 1m / Expire 1h`，对应公开列表和详情基础数据的 `cacheLife("minutes")`。
  - 后台上传、编辑、删除、发布，以及收藏、点赞、评分、评论等会改变公开聚合字段的操作，已接入统一公开 MOD 缓存失效。
- 项目目录结构特点：
  - `src/app/`：路由、页面、布局、API Route Handlers。
  - `src/components/ui/`：基础 UI 原子组件，shadcn/ui 风格。
  - `src/components/layout/`：站点布局、主题、Provider、搜索、骨架屏、动效包装等。
