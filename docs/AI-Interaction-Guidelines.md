# AI交互规范
## 沟通要求
- 表述简洁直白
- 对不易理解的决策简要说明原因
- 大规模代码重构或架构调整前先行征询
- 严禁新增项目需求文档以外的功能
- 未经确认不得删除任何文件

## 工作流程
所有功能开发与缺陷修复统一遵循下述流程：
1. **文档记录**：在`@context/current-feature.md`中编写功能说明
2. **新建分支**：为功能开发、缺陷修复单独创建代码分支
3. **代码实现**：按照`@context/current-feature.md`文档内容完成开发或bug修复
4. **测试校验**：浏览器验证功能可用；后续补充单元测试；执行`npm run build`并修复编译报错
5. **迭代优化**：按需调整代码
6. **提交代码**：编译通过、功能全部正常后才可提交
7. **合并分支**：合并至主分支main
8. **删除分支**：合并完成后清理对应分支
9. **代码核查**：按需定期审核AI生成代码
10. 在`@context/current-feature.md`标记任务完成，并归档至历史记录

**未经许可、编译未通过时禁止提交代码；构建失败须优先修复问题。**

## 分支管理
每项功能、每处bug修复均单独创建分支，分支命名格式：`feature/功能名`或`fix/问题名`；分支合并后申请删除分支。

## 代码提交规范
- 提交前需征得许可，禁止自动提交
- 遵循约定式提交注释（`feat:`新增功能、`fix:`修复缺陷、`chore:`工程维护等）
- 单次提交聚焦单一内容：一个功能/一处问题对应一次提交
- 提交备注中不得出现“Generated With Claude”字样

## 开发受阻处理
- 同一问题尝试2~3次仍无法解决时，停止调试并说明故障详情
- 禁止漫无目的地尝试各类修复方案
- 需求模糊时主动问询确认

## 代码修改准则
- 以最少代码改动完成既定任务
- 无明确要求时，不重构无关代码
- 不额外开发非必需的锦上添花式功能
- 沿用项目现有代码编写规范与架构风格

## 代码评审要点
定期复核AI生成代码，重点核查：
- **安全性**：权限校验、入参合法性校验
- **性能**：无效重复渲染、N+1数据库查询等性能隐患
- **逻辑漏洞**：各类边界场景异常
- **编码规范**：是否和项目现有代码风格保持一致
