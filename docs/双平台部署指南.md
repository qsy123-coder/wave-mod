# 双平台部署指南

> 同一个代码库，随时切换 Vercel 与 Cloudflare Workers 部署。

## 为什么要双平台

| 场景 | 推荐平台 |
|---|---|
| 海外用户访问 | Vercel（全球 CDN 成熟） |
| 中国大陆访问 | Cloudflare（亚洲节点更多，BGP 互联更好） |
| 成本控制 | 各有免费额度，互相补充 |
| 容灾备份 | 一个平台挂了切另一个 |

## 快速命令

```bash
npm run vc:deploy       # 部署到 Vercel
npm run cf:deploy       # 部署到 Cloudflare Workers
npm run cf:build        # 仅构建 Cloudflare（不部署）
```

## 平台对比

| | Vercel | Cloudflare |
|---|---|---|
| **URL** | 你的 Vercel 域名 | `https://wavemod.qsy55882.workers.dev` |
| **运行时** | Node.js | Workers (Edge) |
| **中间件** | ✅ proxy.ts 正常工作 | ❌ 暂时不支持（构建时自动移除） |
| **部署命令** | `vercel deploy` | `cf:build` + `wrangler deploy` |

## 架构说明

### 关键改造：Web Crypto API

所有 `node:crypto` 依赖已替换为 Web Crypto API（同时兼容 Node.js 和 Cloudflare Workers）：

- `src/lib/crypto.ts` — 共享工具（`generateSecureBase64Url`、`hmacSha1Base64`、`utf8ToBase64`）
- `src/app/api/oss/sign/route.ts` — HMAC-SHA1 签名
- `src/actions/auth/auth-actions.ts` — 安全随机数
- `src/app/auth/phone/verify/route.ts` — 安全随机数

### Cloudflare 构建自动化（`scripts/cf-build.mjs`）

由于 Next.js 16 的 `proxy.ts`（中间件）与 `@opennextjs/cloudflare` 在 Windows 上存在兼容性问题，构建脚本会自动：

1. 临时将 `src/proxy.ts` 重命名为 `src/proxy.ts.cf-bak`
2. 执行 `npx opennextjs-cloudflare build`
3. 修补 `.open-next/middleware/handler.mjs` 的 `__dirname` 路径
4. 恢复 `src/proxy.ts`

整个过程对开发者透明，不影响正常工作流。

### Admin 路由保护

| 平台 | 中间件保护 | 服务端保护 |
|---|---|---|
| Vercel | ✅ `proxy.ts`（/admin/:path*） | ✅ `requireAdminUser()` |
| Cloudflare | ❌ 构建时移除 | ✅ `requireAdminUser()` |

所有 API 路由和 Server Actions 都有服务端 `requireAdminUser()` 校验，安全不受影响。

## 配置文件

### `wrangler.jsonc` — Cloudflare Worker 配置

```jsonc
{
  "name": "wavemod",
  "main": ".open-next/worker.js",
  "compatibility_date": "2026-06-09",
  "compatibility_flags": ["nodejs_compat", "global_fetch_strictly_public"],
  "assets": {
    "directory": ".open-next/assets",
    "binding": "ASSETS"
  },
  "vars": {
    // 非敏感环境变量（明文）
    "NEXT_PUBLIC_SITE_URL": "https://wavemod.qsy55882.workers.dev",
    ...
  }
}
```

### 敏感变量（Secrets）

以下变量通过 `wrangler secret put` 加密存储：

- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ADMIN_EMAIL` / `ADMIN_PHONES`
- `ALIYUN_OSS_ACCESS_KEY_ID` / `ALIYUN_OSS_ACCESS_KEY_SECRET`
- `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
- 阿里云短信相关密钥
- `SUPABASE_SEND_SMS_HOOK_SECRET`

## 注意事项

1. **`npm install` 之后** — 如果之前手动修补过 `node_modules/@opennextjs/cloudflare/dist/cli/build/utils/middleware.js`，会被还原。现在 `cf:build` 已通过自动移除 proxy.ts 规避了这个问题。

2. **Windows 兼容性** — `@opennextjs/cloudflare` 建议在 WSL 下运行以获得最佳体验。

3. **环境变量同步** — 修改 `.env.local` 中的变量后，记得同步到 Cloudflare：
   ```bash
   # 非敏感变量 → 更新 wrangler.jsonc 的 vars
   # 敏感变量 → wrangler secret put
   echo "值" | npx wrangler secret put 变量名
   ```

4. **构建产物** — Cloudflare 构建产物在 `.open-next/` 目录，已加入 `.gitignore`。
