# 产品需求文档：每日访客统计

**版本**：1.0
**日期**：2026-10-28
**作者**：Sarah（产品经理）
**需求质量分**：91/100

---

## 一、执行摘要

WaveMod 目前只统计「每个 mod 被看了多少次」，**从来没有统计过每天到底来了多少人**。站长（唯一的用户）无法回答最基本的问题：昨天的访客比前天多还是少？发新 mod 那天流量有没有明显变化？

本功能新增一套独立的站点访问统计：前端在每次页面浏览时打一个轻量点，数据落香港自有计数服务（与现有互动计数同一套），每日只保留 `UV / PV` 两行聚合数据并永久保存。展示端是一个**独立于后台登录体系**的密钥链接页面，因为当前 Supabase 免费出口额度被锁（Auth 接口返回 402），`/admin` 登录实际不可用。

选择这套方案的核心原因是**不依赖 Supabase**：它不读也不写 Supabase，免费额度再次被打穿时本功能照常工作。这是它区别于「再建一张 Supabase 表」的价值所在。

---

## 二、问题陈述

**现状**
- 全站没有访问统计（未接入 Umami / GA / 百度统计）。
- 现有浏览量统计（`deploy/hk-engagement/service.py`）是**按 mod** 的，且去重表只保留最近 2 天，天然拼不出历史每日访客曲线。
- `/admin` 依赖 Supabase Auth 登录，而 Supabase Auth 当前返回 402，站长进不去后台。

**解决方案**
新增「站点级」访问计数：客户端打点 → Next API → 香港计数服务，按上海日历日聚合 UV/PV；另建一个用密钥链接保护的 `/visits` 页面展示趋势。

**业务影响**
站长每天花 10 秒即可掌握站点流量走向；发版日、推广日的流量变化可以被观测到，而不是靠感觉。

| 指标 | 目标 | 衡量方式 |
|---|---|---|
| 功能可用性 | 每日页面可正常打开 | 站长每天访问一次 `/visits` |
| 数据完整性 | 连续 7 天数据无缺口 | 趋势图上 7 个点均有值（可接受的自然 0 除外） |

**验证时间**：上线后连续观察 7 天。

## 五、用户故事与验收标准

### 故事 1：每天看一眼流量

**作为**站长
**我希望**打开一个固定链接就能看到今天和昨天的访客数与浏览量
**以便**判断站点是正常的还是断崖式下跌

**验收标准**
- [ ] 今日、昨日各显示 UV（去重设备数）与 PV（访问次数）两个数字，以及相对前一日的涨跌
- [ ] 数字与香港服务 `/visits` 返回一致
- [ ] 首次访问带 `?key=` 正确时，跳转到一个不带参数的地址并种下 30 天有效的 httpOnly cookie
- [ ] `?key=` 错误或空且无有效 cookie 时，返回 404（不泄露"这里有个统计页"）
- [ ] 页面带 `noindex`，不进入 sitemap，不出现任何导航入口

### 故事 2：看最近 30 天趋势

**作为**站长
**我希望**看到近 30 天每天 UV/PV 的走势
**以便**发现某天异常或确认推广效果

**验收标准**
- [ ] 近 30 天折线图（UV 与 PV 两条线），无需引入新图表库（纯 SVG）
- [ ] 无数据的日期显示为 0，不跳点
- [ ] 图下方有一张 日期 / UV / PV 表格，便于精确读数
- [ ] 页面在 1 秒内可交互（数据来自香港服务，非 Supabase）

### 故事 3：我的访问不污染数据

**作为**站长
**我希望**自己刷页面、调样式时不要把 UV 抬起来
**以便**数字反映真实访客

**验收标准**
- [ ] 打开 `/visits` 成功后，该设备被种上 `wavemod-nocount=1`（30 天有效）
- [ ] 带该标记的设备打点被前端直接跳过（不发请求）
- [ ] 爬虫（UA 含 bot/spider/crawler）的打点不被计入
- [ ] 站点统计与 mod 浏览量统计相互独立，互不影响

## 六、功能需求

### 核心功能 1：访问打点

- **说明**：客户端在每次页面浏览时上报一次。
- **用户流程**：页面加载 / 路由切换 → 读取设备号 → 若带 `nocount` 标记则跳过 → `fetch('/api/visits', {method:'POST', keepalive:true})`。
- **统计口径**：
  - **PV**：每发生一次页面浏览 +1（刷新 +1，站内路由切换 +1）。
  - **UV**：同一上海日历日内，同一设备号只计 1 次。
  - 同一浏览器多标签页、多设备分别计数（与现有互动计数同规则）。
- **边界**：
  - 禁用 JS / 无痕模式关闭标签：不计（可接受）。
  - 设备号取不到（`localStorage` 完全不可用）：该次只计 PV 不计 UV，或整体跳过——**实现时统一选择"整体跳过"**，避免 PV 与 UV 口径混乱。
- **错误处理**：打点失败静默丢弃，绝不影响页面、不弹提示、不重试。

### 核心功能 2：每日聚合存储（香港服务）

- **说明**：`deploy/hk-engagement/service.py` 新增 `visits` 状态段。
- **存储形态**：
  - 当天：`{ "pv": n, "devices": [设备号 hash…] }`（UV = devices 长度，实时去重）。
  - 历史日：冻结为 `{ "pv": n, "uv": n }`，丢弃设备列表。
- **为什么冻结**：永久保留设备列表会让 JSON 无限增长（每天重写整份状态），冻结后每天只占两个整数。
- **接口**：
  - `POST /visit { deviceId, day }` → `{ ok: true }`
  - `GET /visits?days=30` → `{ days: [{ date, uv, pv }], today, yesterday }`
- **镜像与备份**：复用现有 COS 镜像与每小时 `.bak`，不新增机制。

### 核心功能 3：展示页 `/visits`

- **说明**：独立于 `/admin` 的页面，自带密钥门槛。
- **访问门槛**：
  - 服务器 `.env` 新增 `VISITS_TOKEN`（长随机串，只在服务器存在）。
  - `GET /visits?key=<token>`：比对通过 → 种 httpOnly cookie（HMAC 签名，含签发时间，30 天有效）→ 302 到 `/visits`（丢掉 `?key=`，避免留在浏览历史/截图里）。
  - cookie 无效 / 缺失 / 过期 → 404。
  - 比对使用恒定时间比较，避免时序侧信道。
- **页面内容**（server component 渲染）：
  1. 今日 / 昨日：UV、PV 四张大数字卡 + 环比涨跌；
  2. 近 30 天双折线（UV/PV）；
  3. 日期 / UV / PV 明细表（近 30 天，倒序）。
- **样式**：沿用后台既有 neo-brutalist 风格（`neo-card`、粗黑边框 + 硬阴影）。
- **失败态**：香港服务读不到时显示「数据暂不可用」以及上次成功时间，**不显示 0**（0 会被误读为"没人来"）。

### 不在本期范围

- 按页面路径 / 角色页 / mod 详情的细分
- 来源渠道（referrer）、地区、设备、浏览器分布
- 实时在线人数
- 历史数据回填（功能上线前的日期无法补）
- 给普通用户或第二个人看的任何入口
- 修复 Supabase 402 / 恢复后台登录（独立问题，另行处理）

## 七、技术约束

### 性能
- 打点请求不得超过页面首屏关键路径（异步、失败静默）。
- 打点不得让客户端包变大：不引第三方统计 SDK；复用现有 device 模块。
- `/visits` 页面服务端渲染，数据一次取回，无客户端轮询。

### 安全
- `VISITS_TOKEN` 仅存在于服务器环境变量，不出现在任何客户端 bundle。
- cookie 为 httpOnly + SameSite=Lax + Secure（生产）+ HMAC 签名，不可伪造。
- 不带参数访问一律 404，不做"请提供密钥"提示页。
- 页面 `noindex, nofollow`，不进 sitemap，`robots.txt` 不列出该路径（避免反向暴露）。
- 不存 IP、不存 UA、不存 referrer：只存匿名设备号的 hash + 日期。

### 集成
- **香港计数服务**：新增 `/visit` `/visits`，与 `/read` `/apply` 共用 `X-Wavemod-Key` 鉴权与同一份 state 文件。
- **香港 nginx 反代**：需确认 `/api/` 下的 POST 正常透传且不被缓存（现有 2 小时缓存只针对 `/api/mods`，需在部署时复核）。
- **COS 镜像 / 备份**：自动覆盖，无需改动。

### 技术栈
- Next.js App Router（server component + 一个轻量 client 打点组件）
- Python 3 标准库（现有服务无第三方依赖）
- 不新增 npm 依赖（图表手写 SVG）

## 八、MVP 范围与分期

### 一期（MVP，本次）

- 打点：`/api/visits` + 客户端 beacon
- 存储：香港服务 `visits` 聚合（当天去重 + 历史冻结）
- 展示：`/visits` 密钥链接页（今日/昨日卡片 + 30 天折线 + 表格）
- 排除：爬虫 UA、站长设备（`nocount` cookie）

**MVP 定义**：站长能在一个固定链接上看到今天/昨天各来了多少独立访客，且 Supabase 挂掉时不受影响。

### 二期（上线后按需）

- 路径维度（首页 / 角色页 / mod 详情页各自的 UV）
- 来源渠道（只存 referrer 域名）
- 周/月汇总视图、同比环比

### 未来考虑

- 将 `nocount` 标记扩展到"预发域名访问不计入"
- 与 mod 互动数据合并成一张运营看板

## 九、风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 香港服务状态文件被 `visits` 撑大 | 中 | 中 | 历史日冻结为两个整数；上线后核对 `/health` 的 bytes 增长 |
| 香港 nginx 缓存 POST 或拦掉 `/api/visits` | 中 | 高 | 部署后立刻用真实浏览器验证一次 PV 增长；必要时在 nginx 加 `location = /api/visits { proxy_no_cache 1; }` |
| 密钥链接被泄露（截图/转发） | 低 | 中 | cookie 30 天过期；泄露后换 `VISITS_TOKEN` 即可一键失效；页面本身 404 化、无任何外链 |
| 广告拦截插件屏蔽打点 | 低 | 低 | 同源 `/api/visits`，不是常见拦截域名；接受少量丢失 |
| 爬虫 UA 伪造 | 中 | 低 | 只影响 PV 绝对值，UV 仍按设备去重；接受 |
| Supabase 恢复后 `/admin` 与 `/visits` 两套入口并存 | 高 | 低 | 明确 `/visits` 是流量专用入口，不合并；后续二期中可加一个从 `/admin` 跳转的链接 |
| 免费额度 402 持续 | 高 | 无 | 本方案完全不依赖 Supabase |

## 十一、附录

### 名词表
- **UV**：独立访客数，同一上海日历日内按设备号去重
- **PV**：页面浏览次数，每次页面浏览 +1
- **设备号**：`localStorage` 中的匿名 UUID（`wavemod-device-id`），不含身份信息
- **nocount**：站长设备标记，带此 cookie 的设备不参与打点
- **冻结**：日期过去后，把当天的设备列表折算为 UV 数字并丢弃列表
