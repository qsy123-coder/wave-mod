# Product Requirements Document: 手机端首页改版（角色分类直出 + 资源流）与详情抽屉改版

**Version**: 1.3
**Date**: 2026-10-19
**Author**: Sarah (Product Owner)
**Quality Score**: 94/100

---

## Executive Summary

WaveMod 手机端首页目前是一套「桌面内容的手机缩放版」：第一屏是品牌大卡 + 精选轮播，第二屏是 Zenless 大屏舞台、统计条和创作者模块。手机上要滑动整屏才能碰到真正有用的内容（角色分类与资源卡片），而角色分类入口只在顶部汉堡菜单里，层级过深。

本次改版参考 huanmod.top 的手机端信息架构：**去掉轮播、压缩首屏，让用户几乎无需滚动就能看到角色分类，并直接在首页浏览资源**。角色分类点击后**就地筛选**下方卡片流，卡片可就地打开详情抽屉；完整搜索/筛选仍交给 `/mods`。

同时按 huanmod 详情页的视觉优先级重排详情抽屉：**内容区第一块就是大图**；多图时只显示一张，用左右箭头切换，下方保留可点缩略图条。大图放在与站内其他卡片一致的奶油色硬阴影卡片里，图片留白直接取详情页背景色，不使用黑色画框。

首页角色分类与排序控件收进一张奶油色硬阴影面板，避免小卡片直接铺在深色背景上；面板内新增「全部角色」卡片，点击打开全角色抽屉（可就地选择并筛选）。

首页改动**仅限手机端**，桌面端保持逐像素不变；详情抽屉的调整**所有尺寸统一生效**。首页继续保持可静态化。

## Problem Statement

**Current Situation**

| # | 问题 | 现状 |
|---|---|---|
| 1 | 首屏信息效率低 | 品牌大卡 + 轮播占据整个手机视口，用户第一眼看不到任何可浏览的内容 |
| 2 | 角色分类入口太深 | `/mods` 的角色侧栏是 `hidden lg:flex`，手机端只能在汉堡菜单抽屉里找；首页本身没有角色入口 |
| 3 | 第二屏内容与「找资源」无关 | Zenless 大屏舞台、统计条、创作者展示占据手机主滚动区，用户要多次滚动才能到卡片 |
| 4 | 滚动模式不适配长列表 | 手机端仍有整屏 scroll-snap，长列表浏览体验被一屏一屏「卡住」 |
| 5 | 详情抽屉首屏不是预览图 | 打开详情先看到徽标、统计、按钮，预览图被压到「下载方式」下方，第一眼看不到角色图；多图还要在大图与缩略图条之间来回找 |

**Proposed Solution**

1. 手机端第一屏改为 huanmod 式简洁首屏：眉标、标题、两个主入口、搜索框，**移除轮播**。
2. 紧接其后就是角色分类头像墙（单行横向滑动）+ 排序切换 + 资源卡片流（无限滚动）。
3. 点角色 → 就地筛选卡片流（不跳页）；点卡片 → 就地打开详情抽屉。
4. 手机端移除 Zenless 第二屏内容与整屏吸附，改为普通长滚动。
5. 详情抽屉改为「内容区第一块就是大图」：单图展示 + 左右箭头切换 + `N / M` 计数 + 下方可点缩略图条；点击大图仍打开全屏灯箱。
6. 桌面端首页完全不动；详情抽屉的所有尺寸统一使用新布局。

**Business Impact**

- 把「角色分类」从三级入口提升到首页一屏内，降低手机访客的探索成本。
- 首页直接承担「浏览—筛选—看详情」主路径，减少 `/mods` 的跳转流失。
- 不增加服务端渲染负担，首屏 HTML 仍可静态化。

## Success Metrics

用户已明确选择**定性验收 + 正确性护栏**，不设增长 KPI。

**Primary（护栏，必须全部通过）:**

- **首屏可见角色分类**：375–430px 视口下，打开首页不滚动即可看到角色头像墙（至少完整一行）。
- **就地筛选**：点角色后 URL 不变、页面不跳转，下方卡片流在 1 个骨架周期内切换为该角色的内容，选中态清晰。
- **详情抽屉可用**：点任意卡片可就地打开详情抽屉；关闭后角色筛选与滚动位置保持不变。
- **无横向溢出**：`documentElement.scrollWidth === clientWidth`；横向滚动只发生在角色头像条内部。
- **桌面端回归**：≥768px 首页布局与改动前逐像素一致（轮播、第二屏、snap 全部保留）。
- **性能不劣化**：首页仍是可静态化页面；新增数据全部客户端懒加载，不新增服务端全表查询。
- **详情首屏即大图**：打开任意有图的详情抽屉，内容区第一块可见预览大图（无需滚动）。
- **多图可切换**：多图时同一时刻只渲染一张大图，左右箭头可循环切换，`N / M` 计数与缩略图选中态同步。

**Secondary（人工验收）:** 用户本人在真机 375–430px 上确认「直接、好用」。

## User Personas

- **Role**: 从 QQ 群 / 搜索引擎进入，主要用手机浏览
- **Goals**: 快速按角色找到外观资源；先看预览图再决定下载
- **Pain Points**: 首页看不到角色分类；要滚很久才到卡片；分类入口藏在汉堡菜单里
- **Technical Level**: 普通用户，不会主动使用高级筛选

### Secondary: 主理人
- **Role**: 维护站点内容
- **Goals**: 手机上快速抽查首页与资源展示
- **Pain Points**: 手机端首页与桌面端是两套完全不同的优先级

## User Stories & Acceptance Criteria

### Story 1: 打开首页立即看到角色分类

**As a** 手机访客
**I want to** 一进首页就看到角色分类
**So that** 我能直接按角色开始浏览，而不用先看宣传内容

**Acceptance Criteria:**
- [ ] 手机端第一屏不再渲染精选轮播。
- [ ] 首屏包含：眉标、标题「角色外观资源」、主按钮（热度榜 / 安装教程）、搜索框。
- [ ] 首屏高度紧凑，375×667 视口下角色头像墙至少第一行露出。
- [ ] 桌面端首屏与轮播完全不变。

### Story 2: 点角色就地筛选资源

**As a** 手机访客
**I want to** 点一下角色头像就看到该角色的资源
**So that** 不用跳到另一个页面再等加载

**Acceptance Criteria:**
- [ ] 角色头像墙为单行横向滑动，第一格为「全部」；每个格子含头像、名称，选中态与未选中态可区分。
- [ ] 点角色后 URL 不变、不触发路由跳转；卡片流显示加载骨架，随后切换为该角色内容。
- [ ] 再次点已选中的角色保持选中（不重复请求/不闪烁）。
- [ ] 切换角色后卡片流回到列表顶部（避免停在上一批内容的滚动位置）。
- [ ] 角色清单从 `/api/characters` 拉取；失败时显示一行提示，不影响首屏与搜索。

### Story 3: 在首页浏览并打开详情

**As a** 手机访客
**I want to** 在首页无限浏览卡片并就地看详情
**So that** 不跳出首页也能完成「看预览 → 看详情 → 下载」

**Acceptance Criteria:**
- [ ] 卡片流复用现有网格与卡片样式（手机默认 2 列瀑布流）。
- [ ] 下滑接近底部时自动加载下一页；没有更多时显示到底提示。
- [ ] 点卡片打开现有详情抽屉；关闭后角色筛选保持不变。
- [ ] 排序可在「最新 / 热度」间切换，默认「最新」，切换后卡片流刷新。

### Story 4: 桌面端首页不受影响

**As a** 桌面访客 / 主理人
**I want to** 看到与现在完全一致的桌面首页
**So that** 本次移动端改版不引入桌面回归

**Acceptance Criteria:**
- [ ] ≥768px 下渲染原有品牌大卡 + 精选轮播 + 第二屏内容。
- [ ] 桌面端滚动吸附、轮播行为不变。
- [ ] 手机端新增组件不影响桌面端 DOM 交互（隐藏分支不发起数据请求）。

### Story 5: 详情抽屉第一眼看到角色图

**As a** 手机/桌面访客
**I want to** 打开详情就看到角色预览大图，并能左右切换多张图
**So that** 我能快速判断这套外观长什么样，不用先翻过一堆按钮

**Acceptance Criteria:**
- [ ] 详情抽屉内容区第一块为预览大图；标题仍在顶部固定栏，分享/关闭按钮不变。
- [ ] 多图时默认显示第 1 张，同一时刻只显示一张；左右箭头可循环切换。
- [ ] 大图右下角显示 `当前 / 总数`；单图时不显示箭头与计数（或计数显示 1/1）。
- [ ] 大图下方保留一排可点缩略图，当前图高亮；点缩略图切换大图。
- [ ] 点击大图打开全屏灯箱，灯箱内左右箭头与键盘方向键仍可切换。
- [ ] 原「下载方式」下方的预览缩略图区块移除，避免同一组图出现两次。
- [ ] 无预览图时显示等高的占位块，不塌陷、不报错。
- [ ] 大图位于有硬阴影的卡片内；图片留白（竖图两侧）与抽屉背景同色，不出现黑色边。
- [ ] 手机与桌面（抽屉宽度 45%）都使用这套布局。

## Functional Requirements

### Core Features

**Feature 1: 手机端简洁首屏（无轮播）**
- Description: 新建手机专用首屏组件，只保留品牌信息与入口；轮播只属于桌面分支。
- User flow: 打开首页 → 看到标题/按钮/搜索 → 继续下滑即角色分类。
- Edge cases:
  - 搜索框为空提交 → 跳 `/mods`，不产生空查询参数。
  - 键盘弹起时首屏不应被挤坏（搜索框位于正常文档流）。
- Error handling: 搜索使用原生 GET 表单提交，不依赖 JS；JS 不可用也能跳转。

**Feature 2: 角色分类头像墙**
- Description: 单行横向滚动列表，第一格「全部」，其后为库内角色；整组控件与排序放在一张奶油色硬阴影面板内。横条右侧固定一张「全部角色」卡片，点击打开全角色抽屉。
- User flow: 左右滑动选择角色 → 点击 → 下方卡片流筛选；或点「全部角色」→ 在抽屉网格中选择 → 抽屉关闭、横条滚到选中项、卡片流筛选。
- Edge cases:
  - 无头像的角色使用等大占位块，保持行高对齐。
  - 角色数量很多时只横向滚动，不撑破页面宽度。
  - 清单加载失败或为空时显示简洁提示，不阻塞卡片流。
  - 抽屉打开时把当前选中角色滚到可视区中间；选择后横条也自动滚到该项。
- Error handling: 请求失败不重试风暴；保留「全部」状态可用。

**Feature 3: 首页资源流**
- Description: 复用 `ModsInfiniteGrid`，以 `character` + `sort` 为查询键；数据来自 `/api/mods`。
- User flow: 选择/不选择角色 → 浏览卡片 → 无限加载 → 点卡片开抽屉。
- Edge cases:
  - 切换角色/排序时取消旧查询展示（由 queryKey 驱动）。
  - 详情抽屉关闭后不重置筛选。
  - 无结果的分类显示空态而不是无限骨架。
- Error handling: 请求失败展示错误提示与重试入口（沿用网格既有行为）。

**Feature 4: 排序切换**
- Description: 「最新 / 热度」两个按钮/分段控件，默认最新。
- User flow: 点热度 → 卡片流按热度重排。
- Edge cases: 同一排序重复点击不发请求。

**Feature 5: 手机端移除旧第二屏与整屏吸附**
- Description: 手机端不渲染 Zenless 舞台/统计/创作者；滚动改为普通长滚动。
- User flow: 一路向下浏览，无整屏吸附阻挡。
- Edge cases: 桌面端 snap 容器保持原样；移动端隐藏分支不得触发 `/api/home/lower`。

**Feature 6: 详情抽屉大图置顶 + 单图轮播**
- Description: 在 `ModDetailDrawer` 总览标签页的最前面加一块「预览画廊」：固定高度画框内单张大图居中展示，左右箭头循环切换，右下角 `N / M`；下方一排可点缩略图。画廊整体放在奶油色卡片里（`border-4` + 硬阴影），图片留白区域使用详情页背景色，不使用黑色画框。
- User flow: 打开抽屉 → 第一眼看到大图 → 左右箭头或点缩略图切换 → 点大图进灯箱 → 继续下滑看信息与下载。
- Edge cases:
  - 0 张图：渲染等高占位块（图标 + 「暂无预览图」），不显示箭头/计数/缩略图条。
  - 1 张图：不显示箭头；计数可显示 `1 / 1`。
  - 图片宽高比差异大：画框固定高度、`object-contain` 居中，切换时不跳动。
  - 外部存储/被封禁的图：沿用现有 `isExternalStorageUrl` 与图片错误兜底，不新增崩溃路径。
  - 收藏/点赞/评分等操作仍留在下方，不因画廊上移而丢失。
- Error handling: 单图加载失败保留画框与切换能力，不阻塞其余信息展示。

### Out of Scope
- 桌面端**首页**任何布局/样式调整。
- 分站整页详情 `GameModDetailContent`（如 `/wuthering-waves/mods/<id>`）—— 本期只改主站详情抽屉。
- `/mods` 页面本身的改动。
- 首页内联完整搜索（搜索统一跳 `/mods`）。
- 「含直链 / 含预览图」开关（留给 `/mods`）。
- 角色分类全量网格墙（头像墙只做单行横滑）。
- Zenless 第二屏在手机端的保留/迁移。

## Technical Constraints

### Performance
- 首页必须保持可静态化：不新增服务端 `await searchParams / cookies`，不在首页服务端新增全表查询。
- 角色清单与卡片流均客户端加载；隐藏的桌面分支不得发起数据请求。
- 复用现有接口 `/api/characters`（s-maxage=300）与 `/api/mods`（s-maxage=300）。
- 网格按需加载，首屏 JS 不引入新的第三方依赖。

### Security
- 仅使用公开只读接口，不涉及用户态数据；详情抽屉沿用既有登录态处理。

### Integration
- **`ModsInfiniteGrid`**：复用其分页、瀑布流、骨架与状态上报；在页面级滚动下（无滚动容器）应退回视口监听（组件已支持）。
- **`ModDetailDrawer`**：首页用本地状态控制开关；本期同时改造其总览页布局（大图置顶）。现有灯箱（lightbox）与键盘导航逻辑保留，仅把入口从缩略图区移到新画廊。
- **`withCosImageTransform`**：画廊大图沿用 COS 显示尺寸变换，避免直接拉原图。
- **`/api/characters`**：角色清单来源，保持「库内 distinct character」权威口径。
- **`/api/mods`**：分页与筛选参数口径与 `/mods` 完全一致（`character` / `sort` / `page`）。
- **`SessionProvider`**：根布局已提供，网格与抽屉可直接消费。

### Technology Stack
- Next.js 16 App Router + React 19 + Tailwind CSS v4 + TanStack Query
- 不引入新依赖；样式沿用 neo-brutalist 视觉系统
- 目标设备：375–430px 手机；桌面断点 `md`（768px）以上保持原样

## MVP Scope & Phasing

### Phase 1: MVP（本次交付）
- 手机端简洁首屏（无轮播）
- 角色头像墙（单行横滑）+ 就地筛选
- 首页资源流（无限滚动）+ 详情抽屉 + 排序切换

### Phase 2: Enhancements（后续）
- 角色墙支持「展开全部」或分组（热门 / 最新角色）

- 移动端首页埋点（分类点击率、抽屉打开率）

## Risk Assessment

| Risk | Probability | Med | Mitigation Strategy |
|------|------------|-----|---------------------|
| 隐藏的桌面分支仍下载轮播图片/DOM，拖慢手机首屏 | Med | Med | 桌面分支容器用 `hidden md:block`；轮播图保持懒加载；验收时检查手机端网络请求 |
| 手机端拿掉 snap 后影响桌面端 | Low | High | snap 仅放在桌面分支，移动端不在文档流中；桌面逐像素回归 |
| 首页资源流与 `/mods` 使用同一 TanStack Query key，状态互相污染 | Low | Med | 首页使用独立 queryKey 前缀或相同筛选参数下复用（二者语义一致，可接受共享） |
| 详情抽屉打开时 body 滚动锁与首页长滚动冲突 | Med | Med | 复用既有抽屉滚动锁逻辑；真机验收关闭后滚动位置 |
| 角色清单接口失败导致第二屏空 | Low | Med | 保留「全部」并用卡片流兜底；显示提示文案 |
| 首页 HTML 同时包含桌面与移动两套内容，体积增大 | Med | Low | 移动组件为轻量结构；不服务端预渲染卡片流；后续可考虑 UA 分流 |

### C. 设计决策记录

| 决策 | 理由 |
|---|---|
| 手机端直接移除轮播（用户 2026-10-19 追加要求） | 「直接一点，直接放角色分类」；轮播在手机上需要滑过整屏，与本次目标相悖 |
| 角色墙单行横向滑动 | 占高最小，先把资源卡片露出来；与主流频道栏一致 |
| 点角色就地筛选而非跳页 | 减少一次路由往返；符合「首页即浏览页」的目标 |
| 搜索仍跳 `/mods?query=` | 复用完整搜索/排序/筛选，首页不重复实现 |
| 桌面端完全不动 | 首页桌面版是既有视觉标志，本次为移动端专项 |
| 手机端普通长滚动 | 整屏吸附与长列表浏览冲突，且 huanmod 参考站也是普通滚动 |
| 详情抽屉大图置顶、所有尺寸统一 | 用户 2026-10-19 明确要求；预览图是决定「下不下」的核心信息，优先级高于统计与按钮 |
| 多图只显示一张 + 左右箭头 | 与 huanmod 详情页一致；缩略图条只作快速跳转，不再作为主视图重复展示 |
| 分站整页详情不在本期 | 主站 `/mods/<id>` 实际使用抽屉；整页详情只服务分站路由，避免一次改动面过大 |
| 角色/排序控件收进浅色面板 | 深棕页面背景上直接铺白色小卡片对比刺眼、标题也糊；奶油色卡片 + 硬阴影符合站内卡片规范 |
| 「全部角色」做成固定卡片 + 抽屉 | 65 个分类横滑找起来太累；固定入口始终可见，抽屉一屏铺开全部头像 |
| 详情大图用奶油底而非黑底 | 竖图在黑色画框里两侧黑边太重；改为与抽屉背景同色，视觉上与站内卡片一致 |

## Revision 1.3 — 点赞/评分下线与下载量初始化（2026-10-19）

用户追加要求：

1. 首页删除「排序」两个字。
2. 详情抽屉的角色/版本/适配标签移到图片上方。
3. 详情统计行删除「评分」「点赞」，新增「下载量」。
4. 点赞与评分从站内入口彻底移除（统计行、点赞按钮、评论区评分面板、全页详情、Zenless 详情/榜单、卡片评分展示与按评分排序）。
5. 所有 mod 的初始下载量 = 当前浏览量 × 65%，一次性写库；后续仍由下载路由正常累加。

实现口径：

- 统计行固定为 **浏览 / 收藏 / 下载量** 三格；下载量取详情接口的 `downloads`，与数据库一致。
- 数据脚本：`scripts/seed-downloads-from-views.mjs`（默认 dry-run，`--apply` 写库）。
  浏览量为线上 API 的实时展示值；SQL 用 `GREATEST(COALESCE(downloads_count,0), round(views*0.65))`，
  **不会把已有真实下载量改小**，可安全重跑。
- 实测（2026-10-19）：5,484 条 mod，3,536 条发生更新，下载量合计 13 → 15,214；
  1,948 条浏览量为 0，按公式保持 0。
- 点赞/评分相关组件 `like-button.tsx`、`rating-panel.tsx` 已删除；后端 action 保留（不再有 UI 入口）。
- 榜单：删除「评分榜」「RESOURCE LIKES」；详情/卡片/Zenless 各处的评分与点赞展示一并移除。
- 抽屉入场动画改为 CSS `@keyframes`（元素挂载即播放，不依赖下一帧切 class），
  退场仍走 transition；首页网格 memo 化，点击卡片不再触发整片瀑布流重渲染。
  实测连续 3 次开关：挂载 1–4ms，位移 390 → 0、遮罩 0 → 1，动画未再丢失。
- 浏览/下载/收藏合并为一张数据卡（`84 次浏览 · 21 次下载 · 0 次收藏`），
  放在标签下方、图片上方；收藏按钮紧贴在数据卡下面。抽屉内容左右 padding
  从 12px 经 20px 提到 **28px**（桌面 32px）。
